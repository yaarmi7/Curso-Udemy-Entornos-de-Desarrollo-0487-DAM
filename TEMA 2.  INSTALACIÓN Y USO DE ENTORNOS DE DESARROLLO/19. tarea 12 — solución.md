## 1. Mismo proyecto en dos IDEs (1,50 puntos)

Código utilizado en ambos IDEs:

```java
public class Calculadora {

    public static int sumar(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        System.out.println("4 + 5 = " + sumar(4, 5));
    }
}
```

Proceso:

- **VS Code:** con *Extension Pack for Java* y un JDK instalado, creé el proyecto con
  `Ctrl + Shift + P` → *Java: Create Java Project*, añadí la clase y pulsé **Run** sobre el método `main`.
- **IntelliJ IDEA:** `File` → `New` → `Project` → Java, seleccioné el JDK, añadí la clase y pulsé el botón **Run**.

**Resultado en ambos IDEs:** la consola mostró `4 + 5 = 9`.

**Criterios de corrección:** proyecto creado en los dos IDEs (0,50) · código correcto (0,25) · ejecución correcta en
ambos (0,50) · capturas (0,25).

## 6. Elección justificada (1,50 puntos)

### a) Página web con HTML, CSS y JavaScript → **Visual Studio Code** (0,75 puntos)

En las pruebas, VS Code fue el que arrancó más rápido y consumió menos memoria. Además tiene soporte nativo para HTML,
CSS y JavaScript y extensiones muy útiles para web (Live Server, Prettier, ESLint). No hace falta un IDE pesado
para un proyecto de este tipo.

### b) Aplicación empresarial grande en Java con Spring y Maven → **IntelliJ IDEA** (0,75 puntos)

Las pruebas mostraron que, aunque consume más recursos y tarda más en abrir, ofrece un análisis de código y una
refactorización más completos y una integración excelente con Spring, Maven y Gradle. En un proyecto grande, ese
ahorro de tiempo y de errores compensa el mayor consumo. Eclipse sería una alternativa válida si el equipo ya
trabaja con él.

## Conclusión

Probar los IDEs con el mismo proyecto permite sustituir las opiniones por datos: el IDE más ligero es mejor para
proyectos pequeños o equipos con pocos recursos, y el más completo compensa en proyectos grandes. La decisión
correcta depende del proyecto, del equipo y de los recursos disponibles.
