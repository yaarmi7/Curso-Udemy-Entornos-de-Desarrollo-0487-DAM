# TAREA 10 — SOLUCIÓN

## 1. Snippet propio (1,50 puntos)

Proceso realizado:

1. Abrí Visual Studio Code.
2. Fui a `File` → `Preferences` → `Configure Snippets` y seleccioné **Java**.
3. En el archivo `java.json` escribí:

```json
{
  "Imprimir por consola": {
    "prefix": "sout",
    "body": [
      "System.out.println(\"$1\");",
      "$0"
    ],
    "description": "Imprime un mensaje por consola"
  }
}
```

4. Creé `Prueba.java`, escribí `sout` y pulsé `Tab`.

**Resultado**: VS Code insertó `System.out.println("");` con el cursor dentro de las comillas (posición `$1`).
`$0` indica dónde queda el cursor al terminar.

**Criterios de corrección:** JSON válido con `prefix` y `body` (0,75) · uso real del snippet en un `.java` (0,50) ·
captura del resultado (0,25).

## 2. Tarea de compilación (2,00 puntos)

Creé `main.c`:

```c
#include <stdio.h>

int main(void) {
    printf("Hola Mundo\n");
    return 0;
}
```

Y el archivo `.vscode/tasks.json`:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Compilar main.c",
      "type": "shell",
      "command": "gcc main.c -o main",
      "group": {
        "kind": "build",
        "isDefault": true
      },
      "problemMatcher": ["$gcc"]
    }
  ]
}
```

Ejecución:

1. Pulsé **`Ctrl + Shift + B`**. La terminal mostró `Executing task: gcc main.c -o main`.
2. Se generó el ejecutable **`main`** (`main.exe` en Windows).
3. En la terminal ejecuté `./main` (en Windows, `.\main.exe`) y apareció `Hola Mundo`.

**Criterios de corrección:** `tasks.json` válido con `command` y `group` de *build* predeterminado (0,75) · tarea
ejecutada con el atajo (0,50) · ejecutable generado y ejecutado (0,50) · captura de la terminal (0,25).

## 3. Linter (1,50 puntos)

Instalé las extensiones **Python** y **Pylint**. Con `prueba.py` abierto, el panel *Problems* mostró avisos
equivalentes a estos:

| Línea | Código Pylint | Aviso                                                    |
| ----- | ------------- | -------------------------------------------------------- |
| 1     | C0114         | Falta la documentación del módulo (*missing-module-docstring*) |
| 1     | W0611         | Importación sin usar: `os` (*unused-import*)             |
| 3     | C0116         | Falta la documentación de la función (*missing-function-docstring*) |
| 4     | W0612         | Variable sin usar: `resultado` (*unused-variable*)       |

La lista exacta puede variar ligeramente según la versión de Pylint (por ejemplo, algunas versiones también avisan
de que los nombres `a` y `b` son demasiado cortos).

Código corregido (el error lógico estaba en que se devolvía `a` en lugar de `resultado`):

```python
"""Operaciones de ejemplo."""


def calcular(a, b):
    """Devuelve la suma de a y b."""
    resultado = a + b
    return resultado
```

**Resultado**: tras la corrección, el panel *Problems* quedó vacío para esta funcionalidad.

**Criterios de corrección:** Pylint instalado y funcionando (0,25) · al menos tres avisos reales anotados (0,50) ·
código corregido (0,50) · capturas del antes y el después (0,25).

## 4. Formateador y formato al guardar (2,00 puntos)

Instalé **Prettier - Code Formatter** y añadí a `settings.json` (`File` → `Preferences` → `Settings` →
*Open Settings (JSON)*):

```json
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode"
}
```

Código **antes** de guardar:

```javascript
const suma = (a,b) =>{return a+b}
console.log( suma(2,3) )
```

Código **después** de guardar con `Ctrl + S`:

```javascript
const suma = (a, b) => {
  return a + b;
};
console.log(suma(2, 3));
```

Prettier añadió los espacios tras las comas, reorganizó las llaves en varias líneas con indentación, añadió los
puntos y comas y eliminó los espacios sobrantes dentro del paréntesis.

**Criterios de corrección:** Prettier instalado (0,25) · `settings.json` con `formatOnSave` y formateador
por defecto (0,75) · formato aplicado al guardar (0,75) · antes y después documentados (0,25).

## 5. Linter frente a formateador (1,50 puntos)

- El **linter** analiza el código sin ejecutarlo y **avisa** de problemas (errores potenciales, variables sin usar,
  malas prácticas), pero **no modifica** el archivo.
- El **formateador** **reescribe** el código para unificar su aspecto (indentación, espacios, saltos de línea), pero
  **no busca** errores lógicos.

| Herramienta     | Qué automatiza                                           | Ejemplo        |
| --------------- | -------------------------------------------------------- | -------------- |
| **Snippet**     | Escritura de estructuras de código repetidas             | `sout`         |
| **Tarea**       | Compilación y ejecución con un atajo                     | `gcc main.c`   |
| **Linter**      | Detección de errores y malas prácticas                   | Pylint, ESLint |
| **Formateador** | Estilo e indentación uniformes                           | Prettier       |

## 6. Actualización del IDE (1,50 puntos)

En VS Code se comprueba en `Help` → `Check for Updates` y se controla con el ajuste `update.mode`. En IntelliJ,
Eclipse y NetBeans se usa `Help` → `Check for Updates`.

Conviene mantener el IDE actualizado porque las versiones nuevas corrigen errores, mejoran el rendimiento, solucionan
fallos de seguridad y añaden compatibilidad con nuevas versiones de lenguajes y extensiones.

## Conclusión

La automatización se aprende utilizándola: el snippet y la tarea ahorran escritura y comandos, el linter detecta
problemas antes de ejecutar y el formateador mantiene un estilo uniforme sin esfuerzo al guardar.
