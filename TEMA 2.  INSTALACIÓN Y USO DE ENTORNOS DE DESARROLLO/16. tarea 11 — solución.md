# TAREA 11 — SOLUCIÓN

## 1. Java desde la terminal (2,00 puntos)

`Main.java`:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hola Mundo");
    }
}
```

Comandos ejecutados:

```bash
javac Main.java                     # genera Main.class
java Main                           # muestra: Hola Mundo
jar cfe app.jar Main Main.class     # crea app.jar con Main como clase principal
java -jar app.jar                   # muestra: Hola Mundo
jar tf app.jar                      # lista el contenido del JAR
```

Salida de `jar tf app.jar`:

```
META-INF/
META-INF/MANIFEST.MF
Main.class
```

Archivos tras el proceso: `Main.java`, `Main.class` y `app.jar`.

En `jar cfe`, la `c` crea el archivo, la `f` indica su nombre y la `e` define la clase principal (*entry point*).
El archivo `MANIFEST.MF` guarda esa información y es lo que permite ejecutar el JAR con `java -jar`.

**Criterios de corrección:** compilación y ejecución correctas (0,50) · JAR creado con clase principal (0,50) ·
JAR ejecutado con `java -jar` (0,50) · contenido mostrado con `jar tf` y capturas (0,50).

## 2. C con dos archivos fuente (2,00 puntos)

`util.h`:

```c
#ifndef UTIL_H
#define UTIL_H

int sumar(int a, int b);

#endif
```

`util.c`:

```c
#include "util.h"

int sumar(int a, int b) {
    return a + b;
}
```

`main.c`:

```c
#include <stdio.h>
#include "util.h"

int main(void) {
    printf("2 + 3 = %d\n", sumar(2, 3));
    return 0;
}
```

Comandos ejecutados:

```bash
gcc -c main.c -o main.o             # compilación: genera main.o
gcc -c util.c -o util.o             # compilación: genera util.o
gcc main.o util.o -o programa       # enlace: genera el ejecutable
./programa                          # muestra: 2 + 3 = 5
```

Archivos tras el proceso: `util.h`, `util.c`, `main.c`, `main.o`, `util.o` y `programa` (`programa.exe` en Windows).

**Error al enlazar solo `main.o`:**

```bash
gcc main.o -o programa
```

El enlazador muestra un error del tipo:

```
undefined reference to `sumar'
```

**Explicación:** `main.o` contiene la llamada a `sumar`, pero no su código, que está en `util.o`. El compilador no
protesta porque la función está declarada en `util.h`; es el **enlazador** quien detecta que falta la definición. Por
eso el código objeto no es ejecutable por sí solo: hay que enlazar todos los archivos objeto y las librerías.

**Criterios de corrección:** dos archivos objeto generados (0,50) · enlace y ejecución correctos (0,50) · error de
enlace reproducido y anotado (0,50) · explicación del error y listado de archivos (0,50).

## 3. Python con PyInstaller (1,50 puntos)

`saludo.py`:

```python
nombre = input("¿Cómo te llamas? ")
print(f"Hola, {nombre}")
```

Comandos ejecutados:

```bash
python saludo.py                    # ejecución con el intérprete
pip install pyinstaller             # instalación de la herramienta
pyinstaller --onefile saludo.py     # creación del ejecutable
```

Resultado:

- El ejecutable aparece en la carpeta **`dist/`** (`saludo.exe` en Windows o `saludo` en Linux/macOS).
- Se crean además la carpeta `build/` (archivos temporales) y el archivo `saludo.spec` (configuración de la
  construcción).
- Al ejecutar `dist/saludo` el programa funciona **sin necesidad de ejecutar `python`**, porque el ejecutable incluye
  el intérprete y las dependencias.

El ejecutable generado solo sirve para el sistema operativo en el que se creó (un `.exe` de Windows no funciona en
Linux).

**Criterios de corrección:** script ejecutado con Python (0,25) · PyInstaller instalado y ejecutado (0,50) ·
carpeta `dist/` identificada (0,25) · otras carpetas y archivos explicados (0,25) · ejecutable probado (0,25).

## 4. El mismo código en un IDE (1,50 puntos)

Ejemplo con **IntelliJ IDEA**:

1. Creé un proyecto Java y añadí la clase `Main` con el mismo código.
2. `File` → `Project Structure` → `Artifacts` → **+** → `JAR` → `From modules with dependencies`.
3. Seleccioné `Main` como clase principal y pulsé *OK*.
4. `Build` → `Build Artifacts` → *Build*.
5. El JAR apareció en `out/artifacts/<nombre>_jar/<nombre>.jar`.

En otros IDEs:

| IDE      | Cómo se genera el JAR                                                           |
| -------- | ------------------------------------------------------------------------------- |
| Eclipse  | `File` → `Export` → `Java` → **Runnable JAR file**                              |
| NetBeans | `Run` → **Clean and Build Project** (JAR en la carpeta `dist/`)                 |

Comprobación: `java -jar <ruta-del-jar>` muestra `Hola Mundo`. Con `jar tf` el contenido es prácticamente el mismo
que el del JAR de la terminal: `META-INF/MANIFEST.MF` y `Main.class`.

| Aspecto                 | JAR de la terminal                | JAR del IDE                                   |
| ----------------------- | --------------------------------- | --------------------------------------------- |
| Clase `Main.class`      | Sí                                | Sí                                            |
| `MANIFEST.MF`           | Sí, con `Main-Class`              | Sí, con `Main-Class` y datos añadidos por el IDE |
| Ubicación               | Carpeta de trabajo                | Carpeta de salida propia del IDE (`out`, `dist`) |

**Conclusión de la comparación:** el compilador subyacente (`javac`) es el mismo, por lo que el resultado es
equivalente. El IDE solo automatiza los pasos y decide las carpetas de salida.

**Criterios de corrección:** programa creado en el IDE (0,25) · JAR generado desde el IDE con los pasos (0,50) ·
JAR ejecutado con `java -jar` (0,25) · comparación del contenido con el JAR de la terminal (0,50).

## 5. Debug y Release, y tabla de lenguajes (1,50 puntos)

| Aspecto                   | Debug                         | Release                        |
| ------------------------- | ----------------------------- | ------------------------------ |
| Finalidad                 | Desarrollar y depurar         | Distribuir al usuario final    |
| Optimización              | Desactivada                   | Activada                       |
| Información de depuración | Incluida                      | Normalmente omitida            |
| Rendimiento y tamaño      | Menos rápido, mayor tamaño    | Más rápido, menor tamaño       |

| Lenguaje | Tipo         | Archivos generados          | Herramienta utilizada |
| -------- | ------------ | --------------------------- | --------------------- |
| Java     | Híbrido      | `.class`, `.jar`            | `javac`, `jar`        |
| C        | Compilado    | `.o`, ejecutable nativo     | `gcc`                 |
| Python   | Interpretado | `.pyc` (opcional `.exe`)    | `python`, PyInstaller |

## 6. Código objeto, enlazador y tipos de ejecutable (1,50 puntos)

- El **código objeto** es la traducción parcial del código fuente a lenguaje máquina. No es ejecutable porque
  todavía faltan por resolver referencias a funciones que están en otros archivos objeto o en librerías (como se
  comprobó con el error `undefined reference to 'sumar'`).
- El **enlazador** une los archivos objeto y las librerías, resuelve esas referencias y genera el ejecutable final.
- Un **ejecutable nativo** (C) contiene instrucciones de máquina que la CPU ejecuta directamente. Un **JAR**
  (Java) contiene **bytecode**, que necesita una máquina virtual (JVM) para ejecutarse, lo que lo hace portable entre
  sistemas operativos.

## Conclusión

Generar ejecutables en la práctica demuestra que cada lenguaje sigue un camino distinto: C compila y enlaza a un
binario nativo, Java produce bytecode empaquetado en un JAR y Python se ejecuta con un intérprete, aunque puede
empaquetarse. El IDE automatiza estos pasos, pero conocer los comandos permite diagnosticar errores y trabajar en
cualquier entorno.
