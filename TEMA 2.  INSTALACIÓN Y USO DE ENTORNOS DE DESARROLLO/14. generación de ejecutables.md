# 5. Generación de ejecutables

Todo el trabajo de configuración de un entorno de desarrollo tiene un objetivo final: **obtener un programa que pueda
ejecutarse**. En el Tema 1 se estudió el proceso teórico que transforma el código fuente en código objeto y en código
ejecutable. En este apartado se aplica ese conocimiento a la práctica: cómo genera un IDE el ejecutable de un proyecto
en **Java, Python, C# y C/C++**.

Un IDE moderno automatiza todo el proceso (compilar, enlazar y empaquetar) con un solo botón, pero entender qué ocurre
por debajo es imprescindible para diagnosticar errores y para generar ejecutables fuera del IDE.

## 5.1. Repaso: del código fuente al ejecutable

| Fase            | Qué ocurre                                                | Resultado                    |
| --------------- | --------------------------------------------------------- | ---------------------------- |
| **Compilación** | Se traduce el código fuente a código objeto o bytecode    | `.o`, `.obj`, `.class`       |
| **Enlace**      | Se unen los archivos objeto y las librerías               | `.exe`, binario ELF          |
| **Empaquetado** | Se agrupan los archivos finales para distribuirlos        | `.jar`, instalador, `.zip`   |

No todos los lenguajes pasan por las tres fases:

- **C/C++** (compilados): compilación y enlace dan un binario nativo.
- **Java** (híbrido): compilación a bytecode `.class` y empaquetado en `.jar`; se ejecuta en la JVM.
- **C#** (híbrido): compilación a código intermedio (CIL) en archivos `.dll` o `.exe`; se ejecuta en .NET.
- **Python** (interpretado): no necesita compilación previa; se puede empaquetar con herramientas externas.

## 5.2. Generación de ejecutables en Java

### Archivos que intervienen

| Extensión | Descripción                                                    |
| --------- | -------------------------------------------------------------- |
| `.java`   | Código fuente                                                  |
| `.class`  | Bytecode generado por el compilador `javac`                    |
| `.jar`    | Paquete que agrupa clases y recursos (*Java ARchive*)          |

### Proceso desde la línea de comandos

```bash
javac Main.java              # genera Main.class
java Main                    # ejecuta el programa en la JVM
jar cfe app.jar Main Main.class   # crea un JAR ejecutable (clase principal: Main)
java -jar app.jar            # ejecuta el JAR
```

En el comando `jar cfe`: `c` crea el archivo, `f` indica su nombre y `e` define la clase principal (*entry point*).

### Proceso desde el IDE

| IDE           | Cómo se genera el ejecutable                                                       |
| ------------- | ---------------------------------------------------------------------------------- |
| VS Code       | Extensión *Java Extension Pack* → vista *Java Projects* → **Export Jar**           |
| IntelliJ IDEA | `File` → `Project Structure` → `Artifacts` → **JAR**; luego `Build` → `Build Artifacts` |
| Eclipse       | `File` → `Export` → `Java` → **Runnable JAR file**                                 |
| NetBeans      | `Run` → **Clean and Build Project**; el JAR aparece en la carpeta `dist/`          |

### Con herramientas de construcción

- **Maven:** `mvn package` → genera el JAR en la carpeta `target/`.
- **Gradle:** `gradle build` → genera el JAR en `build/libs/`.

## 5.3. Generación de ejecutables en Python

Python es un lenguaje **interpretado**: el código `.py` se ejecuta directamente con el intérprete.

```bash
python main.py
```

Aunque no hace falta compilar, Python genera internamente archivos de **bytecode** (`.pyc`) en la carpeta
`__pycache__` para acelerar futuras ejecuciones.

### Crear un ejecutable independiente

Si se quiere distribuir el programa a usuarios que no tienen Python instalado, se utilizan herramientas externas como
**PyInstaller**:

```bash
pip install pyinstaller
pyinstaller --onefile main.py
```

- `--onefile`: empaqueta todo en un único archivo.
- El resultado aparece en la carpeta `dist/` (`main.exe` en Windows o `main` en Linux/macOS).

### Desde el IDE

En **VS Code** (extensión *Python*) se ejecuta el script con el botón **Run Python File**. En **PyCharm** se usa el
botón *Run*. El empaquetado con PyInstaller se lanza desde la terminal integrada del IDE.

## 5.4. Generación de ejecutables en C#

C# se ejecuta sobre la plataforma **.NET** y es un lenguaje híbrido: se compila a código intermedio (CIL) que luego
ejecuta el entorno de ejecución.

### Proceso desde la línea de comandos

```bash
dotnet new console -n MiApp   # crea un proyecto de consola
dotnet build                  # compila el proyecto
dotnet run                    # compila y ejecuta
dotnet publish -c Release     # genera la versión final para distribuir
```

### Archivos generados

| Carpeta / archivo | Contenido                                                          |
| ----------------- | ------------------------------------------------------------------ |
| `obj/`            | Archivos intermedios del proceso de compilación                    |
| `bin/Debug/`      | Resultado de la compilación en modo depuración                     |
| `bin/Release/`    | Resultado de la compilación optimizada                             |
| `.dll`            | Ensamblado con el código compilado                                 |
| `.exe`            | Ejecutable de arranque (en Windows)                                |

### Desde el IDE

En **Visual Studio** se utiliza `Build` → **Build Solution** (o `Ctrl + Shift + B`) y `Build` → **Publish** para
la versión final. En **VS Code** se emplea la extensión *C# Dev Kit* junto con los comandos `dotnet`.

## 5.5. Generación de ejecutables en C y C++

C y C++ son lenguajes **compilados** que generan **binarios nativos**.

### Proceso paso a paso

```bash
gcc -c main.c -o main.o       # compilación: genera el código objeto
gcc main.o -o main            # enlace: genera el ejecutable
./main                        # ejecución (en Linux/macOS)
```

El mismo resultado se obtiene en un solo paso:

```bash
gcc main.c -o main
```

Para C++ se utiliza `g++` en lugar de `gcc`.

### Opciones frecuentes del compilador

| Opción | Significado                                       |
| ------ | ------------------------------------------------- |
| `-o`   | Nombre del archivo de salida                      |
| `-c`   | Solo compila, no enlaza                           |
| `-g`   | Incluye información de depuración                 |
| `-O2`  | Activa optimizaciones                             |
| `-Wall`| Muestra todas las advertencias habituales         |

### Desde el IDE

| IDE                | Cómo se genera el ejecutable                                         |
| ------------------ | -------------------------------------------------------------------- |
| VS Code            | Tarea de *build* en `tasks.json` con `gcc` (`Ctrl + Shift + B`)      |
| CLion / Code::Blocks | Botón *Build* o *Build and Run*                                    |
| Eclipse CDT        | `Project` → **Build Project**                                        |
| Visual Studio      | `Build` → **Build Solution** (compilador MSVC)                       |

## 5.6. Modos Debug y Release

La mayoría de IDEs permiten compilar un proyecto en dos configuraciones:

| Aspecto        | Debug                                  | Release                              |
| -------------- | -------------------------------------- | ------------------------------------ |
| Objetivo       | Desarrollo y depuración                | Distribución final                   |
| Optimización   | Desactivada                            | Activada                             |
| Información de depuración | Incluida                    | Normalmente omitida                  |
| Tamaño y velocidad | Mayor tamaño, menor velocidad      | Menor tamaño, mayor velocidad        |

Durante el desarrollo se trabaja en modo **Debug**; el ejecutable que se entrega al usuario se genera en modo
**Release**.

## 5.7. Un mismo código fuente con distintos entornos

Un mismo código fuente puede generar su ejecutable desde diferentes IDEs. Por ejemplo, un proyecto Java sencillo puede
compilarse con **IntelliJ**, **Eclipse** o **NetBeans** y producir en los tres casos los mismos archivos `.class`
y un `.jar` equivalente.

Lo que cambia entre entornos es:

- La **estructura de carpetas** del proyecto (`src`, `out`, `bin`, `target`, `dist`).
- Los **archivos de configuración** propios de cada IDE (`.idea/`, `.classpath`, `nbproject/`, `.vscode/`).
- El **proceso de menús** para generar el artefacto final.

Lo que no cambia es el compilador subyacente (`javac`, `gcc`, `dotnet`), por lo que el resultado es compatible entre
entornos si se utiliza la misma versión del JDK o del compilador.

## 5.8. Errores comunes al generar ejecutables

| Problema                                          | Causa habitual                                           |
| ------------------------------------------------- | -------------------------------------------------------- |
| `javac` o `gcc` no se reconocen como comando      | El compilador no está instalado o falta en el `PATH`     |
| `Main class not found`                            | La clase principal no está bien definida en el JAR       |
| `UnsupportedClassVersionError`                    | Se ejecuta con una JVM más antigua que la usada al compilar |
| El ejecutable no arranca en otro equipo           | Faltan librerías o la versión del runtime es diferente   |
| El IDE no encuentra el SDK                        | Ruta del JDK/SDK mal configurada en el proyecto          |

## Resumen

| Lenguaje | Tipo      | Resultado principal            | Herramienta habitual             |
| -------- | --------- | ------------------------------ | -------------------------------- |
| Java     | Híbrido   | `.class` y `.jar`              | `javac`, `jar`, Maven, Gradle    |
| Python   | Interpretado | `.py` (opcional `.exe`)     | `python`, PyInstaller            |
| C#       | Híbrido   | `.dll` / `.exe`                | `dotnet`, Visual Studio          |
| C / C++  | Compilado | Binario nativo                 | `gcc`, `g++`, CMake, Make        |
