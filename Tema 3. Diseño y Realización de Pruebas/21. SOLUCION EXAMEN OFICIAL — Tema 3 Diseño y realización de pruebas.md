# PARTE A — TEORÍA (4 puntos)

## EJERCICIO 1 (1,5 puntos)

a) Define error, defecto y fallo. **(0,4 puntos)**

- **Error:** equivocación cometida por una persona.
- **Defecto:** anomalía que queda en el código como consecuencia del error.
- **Fallo:** comportamiento incorrecto observable cuando se ejecuta el código defectuoso.

*Ejemplo:* el programador escribe `<=` en lugar de `<` (**error**); la línea `if (nota <= 7)` es el **defecto**; al
clasificar la nota 7 el programa devuelve `APROBADO` en lugar de `NOTABLE` (**fallo**).

b) Caja blanca y caja negra. **(0,4 puntos)**

Las pruebas de **caja blanca** se diseñan **conociendo el código** y buscan ejecutar todas sus partes (técnicas:
cobertura de sentencias o decisiones, caminos, complejidad ciclomática). Las de **caja negra** se diseñan **a partir de
la especificación**, sin mirar el código, y comprueban que las salidas son las esperadas (técnicas: clases de
equivalencia, valores límite, conjetura de errores). Son complementarias.

c) Prueba de regresión. **(0,35 puntos)**

Es la que **vuelve a ejecutar las pruebas existentes** para comprobar que un cambio (una corrección, una
refactorización o una nueva funcionalidad) **no ha estropeado lo que ya funcionaba**. Debe realizarse **después de cada
cambio relevante** en el código.

d) Refactorizar. **(0,35 puntos)**

**Refactorizar** es mejorar la estructura interna del código **sin cambiar su comportamiento externo**. Hacen falta
pruebas automáticas porque actúan como **red de seguridad**: permiten comprobar de forma rápida, después de cada paso,
que el comportamiento sigue siendo el mismo.

## EJERCICIO 5 — Diseño y automatización de pruebas (1,5 puntos)

a) **Diseño de casos (0,75 puntos).**

**Clases de equivalencia:**

| Clase | Intervalo           | Tipo      | Resultado esperado | Representante |
| ----- | ------------------- | --------- | ------------------ | ------------- |
| CE-1  | nota < 0            | No válida | Excepción          | -3            |
| CE-2  | 0 ≤ nota < 5        | Válida    | SUSPENSO           | 2.5           |

**Valores límite:**

| Frontera                    | Valores         | Resultado esperado          |
| --------------------------- | --------------- | --------------------------- |

| SUSPENSO / APROBADO         | 4.99 y 5        | SUSPENSO y APROBADO         |
| APROBADO / NOTABLE          | 6.99 y 7        | APROBADO y NOTABLE          |
| NOTABLE / SOBRESALIENTE     | 8.99 y 9        | NOTABLE y SOBRESALIENTE     |
| SOBRESALIENTE / No válida   | 10 y 10.01      | SOBRESALIENTE y Excepción   |

**Criterios de corrección:** clases de equivalencia completas con representantes (0,40) · valores límite de las cinco
fronteras (0,35).

b) **Automatización (0,75 puntos).**

```java
package com.ejemplo.notas;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertThrows;

import org.junit.jupiter.api.Test;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;
import org.junit.jupiter.params.provider.ValueSource;

class NotasTest {

    @Test
    void notaTresEsSuspenso() {
        assertEquals("SUSPENSO", Notas.clasificar(3.0));
    }

    @ParameterizedTest(name = "nota {0} -> {1}")
    @CsvSource({
        "2.5,  SUSPENSO",
        "6,    APROBADO",
        "8,    NOTABLE",
        "9.5,  SOBRESALIENTE",
        "0,    SUSPENSO",
        "4.99, SUSPENSO",
        "5,    APROBADO",
        "6.99, APROBADO",
        "7,    NOTABLE",
        "8.99, NOTABLE",
        "9,    SOBRESALIENTE",
        "10,   SOBRESALIENTE"
    })
    void clasificaSegunLaNota(double nota, String esperado) {
        assertEquals(esperado, Notas.clasificar(nota));
    }

    @ParameterizedTest(name = "nota {0} no es válida")
    @ValueSource(doubles = {-3, -0.01, 10.01, 12})
    void notasNoValidasLanzanExcepcion(double nota) {
        assertThrows(IllegalArgumentException.class, () -> Notas.clasificar(nota));
    }
}
```

En total hay **17 invocaciones** de prueba: 1 + 12 + 4.

**Criterios de corrección:** `@CsvSource` con representantes y límites de las notas válidas (0,35) · `@ValueSource`
con las no válidas y `assertThrows` (0,25) · código compila y se ejecuta (0,15).

## EJERCICIO 6 — Detectar y depurar un defecto (1,5 puntos)

a) **Casos que fallan (0,5 puntos).** Al ejecutar todas las pruebas:

```
[ERROR] Tests run: 17, Failures: 1, Errors: 0, Skipped: 0
```

Falla **un único caso**, el de la nota **7**:

```
nota 7 -> NOTABLE
expected: <NOTABLE> but was: <APROBADO>
```

Los otros 16 pasan, incluidos 6.99 y 8.99. El Test Explorer muestra la fila `nota 7 -> NOTABLE` en rojo.

**Criterios de corrección:** ejecución completa (0,15) · caso fallido identificado (0,20) · mensaje y captura (0,15).

b) **Depuración (0,5 puntos).**

1. Punto de ruptura en la línea `if (nota < 0 || nota > 10)` con *Edit Breakpoint* → *Expression*:
   `nota == 7`.
2. *Debug Test* sobre la prueba parametrizada: el depurador **solo se detiene con `nota = 7.0`**.
3. Avanzando con `F10` se comprueba que:
   - `nota < 0 || nota > 10` es falsa: la nota es válida.
   - `nota < 5` es falsa.
   - **`nota <= 7` es verdadera**, y la ejecución entra en `return "APROBADO"`.

La ejecución **se aparta de lo esperado en la tercera condición** (`if (nota <= 7)`): según la especificación, la nota 7
debería continuar hacia `nota < 9` y devolver `NOTABLE`.

**Criterios de corrección:** punto de ruptura condicional con `nota == 7` (0,20) · avance paso a paso y capturas
(0,15) · línea y rama de desvío identificadas (0,15).

c) **Informe de incidencia (0,5 puntos).**

| Campo                     | Contenido                                                                          |
| ------------------------- | ---------------------------------------------------------------------------------- |
| **ID**                    | INC-001                                                                            |
| **Título**                | La nota 7 se clasifica como APROBADO en lugar de NOTABLE                           |
| **Pasos para reproducir** | Llamar a `Notas.clasificar(7)`                                                     |
| **Resultado esperado**    | `"NOTABLE"` (el intervalo APROBADO es de 5 incluido a 7 excluido)                  |
| **Resultado obtenido**    | `"APROBADO"`                                                                       |
| **Gravedad**              | Media-alta: afecta a una calificación                                              |
| **Línea defectuosa**      | `if (nota <= 7) {`                                                                 |
| **Corrección**            | Cambiar por `if (nota < 7) {`                                                      |

**Criterios de corrección:** informe con los campos indicados (0,30) · línea defectuosa correcta (0,10) · corrección
correcta (0,10).

# EJERCICIO OPCIONAL EXTRA (1,5 puntos)

a) **Conjetura de errores (0,5 puntos).**

```java
@Test
void notaNaNLanzaExcepcion() {
    assertThrows(IllegalArgumentException.class, () -> Notas.clasificar(Double.NaN));
}
```

La prueba **falla** (`Expected IllegalArgumentException to be thrown, but nothing was thrown`). Con `NaN` todas las
comparaciones (`<`, `>`, `<=`) son falsas: el valor supera la validación del rango, no entra en ninguno de los `if`
siguientes y llega a `return "SOBRESALIENTE"`.

Corrección:

```java
if (Double.isNaN(nota) || nota < 0 || nota > 10) {
    throw new IllegalArgumentException("Nota no válida: " + nota);
}
```

Tras el cambio: `Tests run: 18, Failures: 0, Errors: 0, Skipped: 0`.

b) **Cobertura (0,5 puntos).** Plugin añadido en `<build><plugins>`:

```xml
<plugin>
  <groupId>org.jacoco</groupId>
  <artifactId>jacoco-maven-plugin</artifactId>
  <version>0.8.12</version>
  <executions>
    <execution>
      <goals>
        <goal>prepare-agent</goal>
      </goals>
    </execution>
    <execution>
      <id>report</id>
      <phase>test</phase>
      <goals>
        <goal>report</goal>
      </goals>
    </execution>
  </executions>

```

Tras `mvn test`, el informe `target/site/jacoco/index.html` muestra para `Notas` una cobertura del **100% de líneas y
del 100% de ramas**: se ejecutan las tres condiciones de la validación, cada tramo de clasificación y la excepción.

c) **Refactorización (0,5 puntos).** Se seleccionan los valores `5`, `7` y `9` y con `Ctrl + .` → *Extract to
constant* se obtiene:

```java
package com.ejemplo.notas;

public class Notas {

    private static final double UMBRAL_APROBADO = 5;
    private static final double UMBRAL_NOTABLE = 7;
    private static final double UMBRAL_SOBRESALIENTE = 9;

    public static String clasificar(double nota) {
        if (Double.isNaN(nota) || nota < 0 || nota > 10) {
            throw new IllegalArgumentException("Nota no válida: " + nota);
        }
        if (nota < UMBRAL_APROBADO) {
            return "SUSPENSO";
        }
        if (nota < UMBRAL_NOTABLE) {
            return "APROBADO";
        }
        if (nota < UMBRAL_SOBRESALIENTE) {
            return "NOTABLE";
        }
        return "SOBRESALIENTE";
    }
}
```

Tras la refactorización, `mvn test` sigue mostrando **18 pruebas en verde**, lo que confirma que el comportamiento no
ha cambiado.
