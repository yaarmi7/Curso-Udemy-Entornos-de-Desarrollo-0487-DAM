### Valores límite

| Frontera                    | Valores         | Resultado esperado     |
| --------------------------- | --------------- | ---------------------- |
| No válida / INFANTIL        | -1 y 0          | Excepción e INFANTIL   |
| INFANTIL / ADULTO           | 11 y 12         | INFANTIL y ADULTO      |

### Código de `PruebaLimites`

```java
package com.ejemplo.entradas;

public class PruebaLimites {

    static String obtener(int edad) {
        try {
            return Entrada.categoria(edad);
        } catch (IllegalArgumentException e) {
            return "EXCEPCION";
        }
    }

    public static void main(String[] args) {
        int[] edades = {-5, 6, 30, 80, 150, -1, 0, 11, 12, 64, 65, 120, 121};
        String[] esperado = {
            "EXCEPCION", "INFANTIL", "ADULTO", "JUBILADO", "EXCEPCION",
            "EXCEPCION", "INFANTIL", "INFANTIL", "ADULTO", "ADULTO",
            "JUBILADO", "JUBILADO", "EXCEPCION"
        };

        for (int i = 0; i < edades.length; i++) {
            String obtenido = obtener(edades[i]);
            String estado = obtenido.equals(esperado[i]) ? "OK" : "FALLO";
            System.out.println("edad=" + edades[i] + " | esperado=" + esperado[i]
                    + " | obtenido=" + obtenido + " | " + estado);
        }
    }
}
```

edad=80 | esperado=JUBILADO | obtenido=JUBILADO | OK
edad=150 | esperado=EXCEPCION | obtenido=EXCEPCION | OK
edad=-1 | esperado=EXCEPCION | obtenido=EXCEPCION | OK
edad=0 | esperado=INFANTIL | obtenido=INFANTIL | OK
edad=11 | esperado=INFANTIL | obtenido=INFANTIL | OK
edad=12 | esperado=ADULTO | obtenido=INFANTIL | FALLO

edad=65 | esperado=JUBILADO | obtenido=JUBILADO | OK
edad=120 | esperado=JUBILADO | obtenido=JUBILADO | OK

**Defecto:** falla únicamente la edad **12**. Los cinco representantes de las clases de equivalencia pasaron todos;
fue el **valor límite** el que destapó el error.

### Corrección

```java
if (edad < 12) {          // antes: edad <= 12
    return "INFANTIL";
}
```

Tras la corrección, la salida muestra `OK` en las 13 líneas.

**Criterios de corrección:** tabla de clases con representantes (0,50) · valores límite correctos de las cuatro
fronteras (0,50) · `PruebaLimites` ejecutable (0,40) · defecto localizado, corregido y comprobado antes y después
(0,60).

## 2. Cobertura con el depurador (2,50 puntos)

Para ejecutar los conjuntos se utilizó una clase auxiliar con puntos de ruptura en `return "INFANTIL"`,
`return "ADULTO"`, `return "JUBILADO"` y el `throw`:

```java
package com.ejemplo.entradas;

public class PruebaCobertura {
    public static void main(String[] args) {
        int[] conjuntoC = {30, 5, 70, -1};
        for (int edad : conjuntoC) {
            try {
                System.out.println(edad + " -> " + Entrada.categoria(edad));
            } catch (IllegalArgumentException e) {
                System.out.println(edad + " -> excepción");
            }
        }
    }
}
```

### Sentencia alcanzada por cada caso

| Edad | Sentencia final alcanzada |
| ---- | ------------------------- |
| 30   | `return "ADULTO"`         |
| 5    | `return "INFANTIL"`       |
| 70   | `return "JUBILADO"`       |
| -1   | `throw new IllegalArgumentException(...)` |

### Cobertura por conjunto

Decisiones: **D1** `(edad < 0 || edad > 120)`, **D2** `(edad < 12)`, **D3** `(edad < 65)`. Hay 6 resultados posibles
(verdadero y falso de cada una) y 4 sentencias de acción (`throw` y los tres `return`).

| Conjunto             | Sentencias ejecutadas | Cobertura de sentencias | Resultados de decisión recorridos                          | Cobertura de decisiones |
| -------------------- | --------------------- | ----------------------- | ---------------------------------------------------------- | ----------------------- |
| **A** = {30}         | 1 de 4                | **25%**                 | D1 falsa; D2 falsa; D3 verdadera → 3 de 6                  | **50%**                 |
| **B** = {30, 5, 70}  | 3 de 4                | **75%**                 | D1 falsa; D2 falsa y verdadera; D3 verdadera y falsa → 5 de 6 | **83,3%**            |
| **C** = {30, 5, 70, -1} | 4 de 4             | **100%**                | Los 6 resultados                                           | **100%**                |

En el conjunto B, el único resultado que falta es **D1 verdadera** (una edad no válida).

### Conjunto mínimo para el 100% de decisiones

Un conjunto como **{-1, 5, 30, 70}** (el propio conjunto C) alcanza el 100%. **No puede haber uno con menos de 4
casos** porque el método tiene **cuatro salidas distintas y excluyentes** (`throw`, INFANTIL, ADULTO y JUBILADO), y cada
entrada concreta solo recorre una de ellas. Para obtener D1 verdadera hace falta una entrada no válida; para D2
verdadera, una edad infantil; para D3 verdadera, una edad adulta; y para D3 falsa, una edad de jubilado.

**Nota:** con el conjunto C se logra el 100% de decisiones, pero **no** el 100% de cobertura de **condiciones**, porque
la condición simple `edad > 120` nunca llega a ser verdadera (haría falta, por ejemplo, la edad 121).

**Criterios de corrección:** uso del depurador y capturas de las sentencias alcanzadas (0,75) · cobertura de
sentencias de los tres conjuntos (0,50) · cobertura de decisiones de los tres conjuntos (0,75) · conjunto mínimo y
justificación (0,50).

## 3. Conjetura de errores (2,50 puntos)

`PruebaConjetura.java`:

```java
package com.ejemplo.banco;

public class PruebaConjetura {

    static void rechaza(String id, String descripcion, Runnable accion) {
        String resultado;
        try {
            accion.run();
            resultado = "no lanza excepción";
        } catch (IllegalArgumentException e) {
            resultado = "IllegalArgumentException";
        }
        String estado = resultado.equals("IllegalArgumentException") ? "OK" : "FALLO";
        System.out.println(id + " | " + descripcion + " | esperado=IllegalArgumentException"
                + " | obtenido=" + resultado + " | " + estado);
    }

    public static void main(String[] args) {
        rechaza("J-01", "Cuenta con saldo inicial NaN",
                () -> new CuentaBancaria(Double.NaN));

        rechaza("J-02", "ingresar(NaN)",
                () -> new CuentaBancaria(100).ingresar(Double.NaN));

        rechaza("J-03", "ingresar(+Infinity)",
                () -> new CuentaBancaria(100).ingresar(Double.POSITIVE_INFINITY));

        rechaza("J-04", "retirar(NaN)",
                () -> new CuentaBancaria(100).retirar(Double.NaN));

        // J-05: diez ingresos de 0.1 comparados con igualdad exacta
        CuentaBancaria c5 = new CuentaBancaria(0);
        for (int i = 0; i < 10; i++) {
            c5.ingresar(0.1);
        }
        System.out.println("J-05 | 10 ingresos de 0.1 | esperado=1.0 | obtenido=" + c5.getSaldo()
                + " | " + (c5.getSaldo() == 1.0 ? "OK" : "FALLO"));

        // J-06: desbordamiento
        CuentaBancaria c6 = new CuentaBancaria(0);
        c6.ingresar(Double.MAX_VALUE);
        c6.ingresar(Double.MAX_VALUE);
        System.out.println("J-06 | dos ingresos de Double.MAX_VALUE | esperado=saldo finito | obtenido="
                + c6.getSaldo() + " | " + (Double.isInfinite(c6.getSaldo()) ? "FALLO" : "OK"));
    }
}
```

### Salida

```
J-01 | Cuenta con saldo inicial NaN | esperado=IllegalArgumentException | obtenido=no lanza excepción | FALLO
J-02 | ingresar(NaN) | esperado=IllegalArgumentException | obtenido=no lanza excepción | FALLO
J-03 | ingresar(+Infinity) | esperado=IllegalArgumentException | obtenido=no lanza excepción | FALLO
J-04 | retirar(NaN) | esperado=IllegalArgumentException | obtenido=no lanza excepción | FALLO
J-05 | 10 ingresos de 0.1 | esperado=1.0 | obtenido=0.9999999999999999 | FALLO
J-06 | dos ingresos de Double.MAX_VALUE | esperado=saldo finito | obtenido=Infinity | FALLO
```

### Clasificación de los resultados

| Caso | ¿Qué ocurre?                                                                                         | Clasificación                           |
| ---- | ---------------------------------------------------------------------------------------------------- | --------------------------------------- |
| J-01 | `NaN < 0` es falso, así que `NaN` pasa la validación y el saldo queda en `NaN`                       | **Defecto real** de validación          |
| J-02 | `NaN <= 0` es falso, así que se suma `NaN` al saldo                                                  | **Defecto real** de validación          |
| J-03 | `Infinity <= 0` es falso, así que el saldo pasa a ser infinito                                       | **Defecto real** de validación          |
| J-04 | `NaN <= 0` y `NaN > saldo` son falsos, así que `saldo -= NaN` deja el saldo en `NaN`                 | **Defecto real** de validación          |
| J-05 | 0,1 no tiene representación exacta en binario y el error se acumula                                  | **Comportamiento de los decimales**: la prueba debe comparar con tolerancia (por ejemplo, `1e-9`) |
| J-06 | La suma desborda el rango de `double` y da infinito                                                  | **Defecto de diseño / limitación**: falta controlar el desbordamiento |

**Conclusión:** cinco de los seis casos revelan problemas reales o de diseño que ninguna clase de equivalencia ni
valor límite habría descubierto. Para dinero, a largo plazo conviene usar `BigDecimal` en lugar de `double`. La
corrección de la validación se realizará en la Tarea 16, apoyada en pruebas automáticas.

**Criterios de corrección:** al menos 6 entradas sospechosas bien elegidas (0,75) · resultado esperado según la
especificación (0,50) · salida real (0,50) · clasificación correcta entre defectos y comportamiento decimal (0,75).

## 4. Complejidad ciclomática (1,50 puntos)

| Método              | Decisiones simples contadas                                              | V(G) |
| ------------------- | ------------------------------------------------------------------------ | ---- |
| `retirar`           | `cantidad <= 0`, `cantidad > saldo` (2)                                  | 2 + 1 = **3** |
| `Entrada.categoria` | `edad < 0`, `edad > 120`, `edad < 12`, `edad < 65` (4, contando cada condición de `||`) | 4 + 1 = **5** |

**Caminos independientes de `retirar`:**

1. `cantidad <= 0` verdadera → lanza `IllegalArgumentException`.
2. `cantidad <= 0` falsa y `cantidad > saldo` verdadera → lanza `IllegalStateException`.
3. `cantidad <= 0` falsa y `cantidad > saldo` falsa → resta del saldo.

Hacen falta **como mínimo 3 casos de prueba**, el mismo número que V(G), uno por camino independiente. En
`categoria` hacen falta al menos 5: edad menor que 0, edad mayor que 120, INFANTIL, ADULTO y JUBILADO.

## 5. Caja blanca frente a caja negra, y cobertura al 100% (1,50 puntos)

| Aspecto          | Caja blanca                                       | Caja negra                                        |
| ---------------- | ------------------------------------------------- | ------------------------------------------------- |
| Se basa en       | El código fuente                                  | La especificación                                 |
| Ventaja          | Asegura que se ejecuta todo el código             | Detecta funcionalidades que faltan o son incorrectas |
| Limitación       | No detecta lo que no se programó                  | No sabe qué partes del código han quedado sin probar |
| Técnicas         | Cobertura, caminos, complejidad ciclomática       | Clases de equivalencia, valores límite, conjetura de errores |

**Una cobertura del 100% no garantiza que no haya defectos.** Ejemplo:

```java
// Especificación: devuelve true si la persona tiene 18 años o más
public static boolean esMayorDeEdad(int edad) {
    return edad > 18;      // defecto: debería ser >=
}
```

Con las pruebas `esMayorDeEdad(30)` (verdadero) y `esMayorDeEdad(10)` (falso) se logra el **100% de cobertura de
sentencias y de decisiones**, pero el defecto, que solo se manifiesta con `18`, **no se detecta**. La cobertura mide
qué código se ha ejecutado, no si se han probado los valores adecuados. Es necesario combinarla con los **valores
límite** de la caja negra.

## Conclusión

Las técnicas de caja negra y de caja blanca se complementan: los valores límite encontraron el defecto de los 12
años, la cobertura permitió medir qué partes del código se habían recorrido y la conjetura de errores reveló
problemas con `NaN` e infinitos que ninguna otra técnica habría descubierto.
