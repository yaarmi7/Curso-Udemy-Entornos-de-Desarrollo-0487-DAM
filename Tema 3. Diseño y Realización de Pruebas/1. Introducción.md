# INTRODUCCIÓN AL TEMA 3 — DISEÑO Y REALIZACIÓN DE PRUEBAS

Ningún programa nace perfecto. Incluso los desarrolladores más experimentados cometen errores, y cuanto más grande es
un proyecto, más lugares hay donde un fallo puede esconderse. Un cálculo mal redondeado, una condición con un `<` donde
debía haber un `<=` o un caso que nadie pensó pueden provocar desde una molestia al usuario hasta pérdidas económicas o
riesgos para la seguridad.

Por eso, en el desarrollo profesional **probar el software no es una fase opcional que se hace al final si queda
tiempo**: es una actividad planificada, sistemática y, siempre que es posible, automatizada. Este tercer tema del módulo
se centra en **cómo diseñar, ejecutar y automatizar pruebas**, y en cómo usar las herramientas del entorno de
desarrollo para detectar, localizar y corregir errores con confianza.

A lo largo del tema se trabajará siempre con **Java en Visual Studio Code**, utilizando el *Extension Pack for Java*,
**Maven**, **JUnit 5**, el depurador integrado y el control de versiones con **Git**.

## Las pruebas como garantía de calidad

Probar un programa no consiste en ejecutarlo "a ver si funciona". Un buen proceso de pruebas implica:

- decidir **qué** se va a probar y **con qué criterios** se considerará correcto,
- diseñar **casos de prueba** con entradas y resultados esperados,
- ejecutarlos y **comparar** lo obtenido con lo esperado,
- registrar los defectos encontrados y corregirlos,
- **repetir** las pruebas cada vez que el código cambia.

Una idea clave que se repetirá durante todo el tema: **las pruebas pueden demostrar que hay errores, pero nunca que no
los hay**. Por eso importa tanto diseñar pocos casos, pero bien elegidos.

## Un hilo conductor: tres programas pequeños

Para que las prácticas tengan continuidad, durante el tema se trabajará sobre un mismo proyecto Maven con unas pocas
clases sencillas: una **cuenta bancaria**, un **clasificador de entradas por edad** y una **factura con descuentos**.
Algunas de ellas contienen errores a propósito. Parte del trabajo consistirá en **encontrarlos con pruebas bien
diseñadas**, depurarlos y corregirlos, guardando cada paso en un repositorio Git.

## Pruebas, depuración y refactorización: tres herramientas distintas

- **Probar** consiste en descubrir si hay un problema.
- **Depurar** consiste en localizar la causa de un problema ya detectado.
- **Refactorizar** consiste en mejorar el diseño del código sin cambiar su comportamiento, apoyándose en pruebas que
  confirmen que nada se ha roto.

Dominar las tres es lo que permite modificar un programa con seguridad, algo imprescindible en cualquier equipo
profesional.

## Objetivo del Tema 3

Al finalizar este tema, el estudiante será capaz de:

- Planificar pruebas y redactar casos de prueba claros y reproducibles.
- Identificar los diferentes tipos y niveles de pruebas y saber cuándo usar cada uno.
- Diseñar casos de prueba con clases de equivalencia, valores límite y conjetura de errores.
- Analizar la cobertura del código y calcular su complejidad ciclomática.
- Escribir y ejecutar pruebas unitarias con JUnit 5 en Visual Studio Code.
- Depurar código con puntos de ruptura, ejecución paso a paso e inspección de variables.
- Refactorizar código con apoyo de pruebas automáticas.
- Controlar las versiones de un proyecto con Git desde el propio entorno de desarrollo.

Este conocimiento es imprescindible para los siguientes temas del módulo, donde se trabajará con optimización,
documentación y diagramas.
