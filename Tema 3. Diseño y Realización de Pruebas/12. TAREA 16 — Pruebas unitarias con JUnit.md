# TAREA 16 — Pruebas unitarias con JUnit

**Distribución de la puntuación**: Práctica con el ordenador **7 puntos (70%)** · Teoría **3 puntos (30%)**

**Material necesario**: el proyecto `pruebas-tema3` en Visual Studio Code con el *Extension Pack for Java*, JDK 17 y
Maven. Las clases `CuentaBancaria` y `Entrada` están como las dejaste en las tareas anteriores (`CuentaBancaria` con el
límite de `retirar` corregido y `Entrada` con `edad < 12`).

**Entrega**: un documento con tus respuestas, capturas de pantalla del *Test Explorer* y de la terminal, el `pom.xml`
final y el código de las clases de prueba.

**Especificación completa de `CuentaBancaria` para esta tarea** (ampliada con lo descubierto en la Tarea 15):

- El saldo inicial debe ser un número **finito y mayor o igual que 0**; si no, `IllegalArgumentException`.
- `ingresar(cantidad)` exige una cantidad **finita y mayor que 0**; si no, `IllegalArgumentException`.
- `retirar(cantidad)` exige una cantidad **finita y mayor que 0** (si no, `IllegalArgumentException`) y que **no
  supere el saldo** (si lo supera, `IllegalStateException`). Se puede retirar exactamente todo el saldo.
- Un número es **finito** si no es `NaN` ni infinito.

## PARTE PRÁCTICA (7 puntos)

1. **Configurar JUnit 5.** Modifica el `pom.xml` para añadir JUnit Jupiter y el plugin Surefire (consulta la

   verde y también con `mvn test`. Entrega el `pom.xml`, capturas del Test Explorer y la salida de `mvn test`.
   ***(1.00 punto)***

2. **Pruebas de `CuentaBancaria`.** Amplía la clase de prueba hasta tener **al menos 8 pruebas** basadas en la

   incluir: retirar exactamente todo el saldo, retirar más que el saldo, cantidades cero y negativas, y valores no
   finitos (`NaN` e infinito) en `ingresar`, `retirar` y en el constructor. Ejecútalas y entrega el código, una captura
   del Test Explorer **con las pruebas que fallan** y el resumen de `mvn test`. ***(2.00 puntos)***

3. **Pruebas parametrizadas.** Crea `EntradaTest` con una prueba `@ParameterizedTest` con `@CsvSource` que cubra los
   **valores límite** de `Entrada.categoria` (0, 11, 12, 64, 65 y 120) y otra con `@ValueSource` para las edades no

   (`edad <= 12`), ejecuta de nuevo y anota qué fila falla y cómo la identifica VS Code. Restaura el código correcto.
   Entrega el código, una captura del resultado con el fallo y una captura con todo en verde. ***(1.50 puntos)***

4. **Depurar y corregir.** Toma una de las pruebas que fallan en el apartado 2 (por ejemplo

5. **Cobertura con JaCoCo.** Añade el plugin JaCoCo al `pom.xml`, ejecuta `mvn test` y abre
