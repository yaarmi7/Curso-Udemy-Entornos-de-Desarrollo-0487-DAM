# TAREA 18 — Control de versiones con Git

**Distribución de la puntuación**: Práctica con el ordenador **7 puntos (70%)** · Teoría **3 puntos (30%)**

**Material necesario**: el proyecto `pruebas-tema3` en Visual Studio Code con todo el código y las pruebas de las
tareas anteriores (todas las pruebas en verde), Git instalado y, opcionalmente, una cuenta de GitHub.

**Entrega**: un documento con tus respuestas, capturas de la vista de control de código fuente de VS Code, la salida
de los comandos de Git que se indican y el código modificado.

## PARTE PRÁCTICA (7 puntos)

1. **Configuración e inicio del repositorio.** En la terminal de VS Code comprueba que Git está instalado
   (`git --version`) y configura tu nombre, tu correo y la rama inicial `main`. Inicializa el repositorio en la carpeta
   del proyecto (desde la vista de control de código fuente con *Initialize Repository* o con `git init`). Crea un
   archivo `.gitignore` que excluya `target/`, `*.class` y los archivos de IDE. Haz el **primer commit** que incluya
   solo `pom.xml` y `.gitignore`. Entrega la salida de `git --version`, de `git config user.name` y
   `git config user.email`, una captura de la vista de control de código fuente **antes** del commit y la salida de
   `git log --oneline` **después**. ***(1.50 puntos)***

2. **Commits significativos y remoto.** Prepara y confirma por separado, usando el botón `+` de VS Code, **dos commits
   más**: uno con el código de producción (`src/main`) y otro con las pruebas (`src/test`), con mensajes claros.
   Después envía el repositorio a un remoto: publícalo en **GitHub** con *Publish Branch* o, si no tienes cuenta,
   crea un remoto local con `git init --bare ../remoto.git`, asócialo con `git remote add origin` y haz `git push`.
   Entrega los tres mensajes de commit, la salida de `git log --oneline`, una captura de la vista de diferencias de un
   archivo y el resultado de `git remote -v`. ***(1.50 puntos)***

3. **Rama de corrección y fusión.** Crea la rama `fix/desbordamiento` y, siguiendo el enfoque de pruebas primero:
   - Añade a `CuentaBancariaTest` una prueba que compruebe que **dos ingresos de `Double.MAX_VALUE`** lanzan
     `IllegalStateException` (hoy el saldo pasa a infinito) y haz un **commit** con la prueba fallando.
   - Corrige `ingresar` para que lance `IllegalStateException` si el nuevo saldo sería infinito, comprueba con todas las
     pruebas en verde y haz un **segundo commit**.
   - Vuelve a `main`, **fusiona** la rama, comprueba el resultado y **borra** la rama.

   Entrega la prueba y el código añadidos, la salida de `mvn test`, la de `git merge` y la del historial con
   `git log --oneline --graph --all`. ***(2.00 puntos)***

4. **Provocar y resolver un conflicto.** Crea **dos ramas a partir del mismo commit** de `main` que modifiquen **la
   misma línea** del mensaje de la excepción de `ingresar`:
   - `feature/mensajes-claros`: `"Cantidad a ingresar no válida (debe ser finita y positiva)"`.
   - `feature/mensajes-cortos`: `"Ingreso no válido"`.

   Fusiona la primera en `main`, y después la segunda. Debe aparecer un **conflicto**. Entrega una captura del
   conflicto con sus marcas, resuélvelo en VS Code eligiendo un texto final de tu elección, ejecuta las pruebas para
   comprobar que siguen en verde y confirma la fusión. Entrega el archivo antes y después de resolverlo, el comando o
   acción de VS Code utilizados y el historial con `git log --oneline --graph --all`. ***(2.00 puntos)***

## PARTE TEÓRICA (3 puntos)

5. Explica con un dibujo o esquema las **tres áreas** de Git (directorio de trabajo, área de preparación y
   repositorio), qué hace `git add` y `git commit`, y qué es una **rama** y una **fusión**. ***(1.50 puntos)***

6. Explica la diferencia entre sistemas de control de versiones **locales, centralizados y distribuidos**, entre **Git
   y GitHub**, para qué sirve `.gitignore` y escribe **tres ejemplos** de buenos mensajes de commit relacionados con
   este tema. ***(1.50 puntos)***
