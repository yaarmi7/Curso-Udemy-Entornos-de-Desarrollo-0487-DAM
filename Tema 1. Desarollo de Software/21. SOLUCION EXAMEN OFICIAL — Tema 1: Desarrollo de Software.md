## EJERCICIO 1 
Un usuario afirma que “un programa es solo un archivo que está en el ordenador”. A partir de esta afirmación, 
explica qué es realmente un programa informático y cómo se ejecuta dentro de un sistema. **Total: 1,5 puntos**

a) Explica qué es un programa como entidad estática (archivo). **(0,4 puntos)**

Un programa como entidad estática es **un archivo que contiene instrucciones escritas en un 
lenguaje de programación**, almacenado en un dispositivo (por ejemplo, programa.exe, 
main.py). 

b) Explica qué es un programa como proceso en ejecución. **(0,4 puntos)**

Un programa como proceso es **el conjunto de instrucciones cargadas en memoria y 
ejecutándose activamente**, gestionado por el sistema operativo. 

c) Describe el papel de la CPU en la ejecución del programa. **(0,35 puntos)**

La CPU **interpreta y ejecuta las instrucciones del programa**, realizando operaciones 
aritméticas, lógicas y de control de flujo. 

d) Describe el papel de la RAM en la ejecución del programa. **(0,35 puntos)**

La RAM **almacena temporalmente el programa en ejecución y sus datos**, permitiendo 
acceso rápido para que la CPU trabaje. 


## EJERCICIO 2 
Un estudiante confunde los distintos tipos de código que intervienen en el desarrollo de software. 
Debes redactar una explicación clara que le permita diferenciar cada uno y entender su función en el proceso de 
construcción de un programa. **Total: 1,5 puntos**

a) Define código fuente y pon un ejemplo. **(0,4 puntos)**

El código fuente es **el texto escrito por el programador** en un lenguaje de programación. 
Ejemplo: main.c, App.java. 

b) Define código objeto y explica por qué no es ejecutable. **(0,4 puntos)**

El código objeto es **la traducción parcial del código fuente a lenguaje máquina**, pero **no es 
ejecutable** porque aún faltan librerías y símbolos por enlazar. 

c) Define código ejecutable y pon un ejemplo según el sistema operativo. **(0,35 puntos)**

El código ejecutable es **el archivo final que el sistema operativo puede ejecutar 
directamente**. Ejemplo: .exe en Windows, binario ELF en Linux. 

d) Explica qué es el bytecode y en qué lenguajes aparece. **(0,35 puntos)**

El bytecode es **un código intermedio** generado por lenguajes híbridos como **Java (JVM)** o 
**C# (CLR)**. 

## EJERCICIO 3 
En un proyecto se utilizan distintos lenguajes y el equipo necesita entender cómo se ejecuta cada uno. 
Debes explicar las diferencias entre compilación, interpretación y ejecución en máquina virtual. **Total: 1,5 puntos**

a) Explica qué hace un compilador y qué archivo genera. **(0,4 puntos)**

Un compilador **traduce el código fuente a código objeto** y detecta errores de sintaxis y tipos. 
Genera archivos .o, .obj o .class (según lenguaje). 

b) Explica qué hace un intérprete y cómo ejecuta el código. **(0,4 puntos)**

Un intérprete **lee y ejecuta el código línea a línea**, sin generar ejecutables nativos. Ejemplo: 
Python. 

c) Explica qué es una máquina virtual y cómo ejecuta el bytecode. **(0,35 puntos)**

Una máquina virtual **ejecuta bytecode**, interpretándolo y optimizándolo en tiempo real (JIT). 
Ejemplo: JVM, CLR. 

d) Indica una ventaja técnica de usar máquinas virtuales. **(0,35 puntos)**

Ventaja técnica: **portabilidad total** entre sistemas operativos.

## EJERCICIO 6 
Un alumno quiere entender cómo se transforma el código fuente en un ejecutable dentro de un entorno de desarrollo. 
Describe el proceso completo de forma clara y ordenada. **Total: 1,5 puntos**

a) Explica qué ocurre en la fase de compilación. **(0,4 puntos)**

En la compilación, el compilador **traduce el código fuente a código objeto**, comprobando 
sintaxis y tipos. 

b) Explica qué ocurre en la fase de enlace. **(0,4 puntos)**

En el enlace, el enlazador **une los archivos objeto y las librerías**, generando el ejecutable 
final. 

c) Indica qué archivos se generan en cada fase. **(0,35 puntos)*+

Compilación → .o, .obj, .class
Enlace → .exe, binario ELF, .app 

d) Explica la diferencia entre ejecutable nativo y bytecode. **(0,35 puntos)**

Ejecutable nativo: se ejecuta directamente en la CPU. Bytecode: necesita una máquina virtual.
