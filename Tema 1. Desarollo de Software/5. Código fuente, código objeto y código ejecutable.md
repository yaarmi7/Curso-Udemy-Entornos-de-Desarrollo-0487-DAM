# 2. Código fuente, código objeto y código ejecutable
Este apartado es fundamental porque explica **cómo pasa un programa desde la idea del desarrollador hasta convertirse 
en algo que un ordenador puede ejecutar**.

Aquí se introduce el concepto de traducción del código, el papel del compilador y la diferencia entre ejecutables nativos 
y bytecode.

## 2.1. Código fuente
El **código fuente** es el texto que escribe el programador utilizando un lenguaje de programación.

Es legible por humanos, pero **no** por la CPU.

Ejemplos de código fuente:
* main.py en Python
* App.java en Java
* program.cs en C#
* main.c en C

El código fuente:
* contiene instrucciones estructuradas,
* sigue una sintaxis concreta,
* puede incluir comentarios,
* puede organizarse en funciones, clases o módulos.

El ordenador *no puede ejecutar directamente* el código fuente.

Necesita transformarlo.

## 2.2. Código objeto
El **código objeto** es el resultado de la primera fase de la compilación.
Es un archivo que contiene instrucciones en lenguaje máquina, pero **no es un programa completo**.

Características:
* está parcialmente traducido,
* depende de otros módulos o librerías,
* no puede ejecutarse por sí solo.

Ejemplos:
* main.o en C
* module.obj en C++

El código objeto suele generarse **por cada archivo fuente**.

Luego se unen mediante el enlazador.

## 2.3. Código ejecutable
El **código ejecutable** es el archivo final que el sistema operativo puede ejecutar directamente.

Ejemplos:
* .exe en Windows
* binarios ELF en Linux
* aplicaciones .app en macOS

Para obtener un ejecutable:
1. El compilador traduce el código fuente a código objeto.
2. El enlazador une todos los objetos y librerías.
3. Se genera el ejecutable final.

Este ejecutable contiene **todas las instrucciones necesarias** para que la CPU pueda ejecutarlo sin depender 
del código fuente.

## 2.4. Bytecode y máquinas virtuales
Algunos lenguajes no generan ejecutables nativos, sino **bytecode**, un código intermedio que necesita una 
máquina virtual para ejecutarse.

Ejemplos:
* **Java → JVM (Java Virtual Machine)**
* **C# → CLR (Common Language Runtime)**

El bytecode:
* no es código fuente,
* no es código máquina,
* es un formato intermedio optimizado.

Ventajas de las máquinas virtuales:
* portabilidad (el mismo programa funciona en Windows, Linux, macOS),
* seguridad,
* gestión automática de memoria,
* optimización en tiempo de ejecución (JIT).

## 2.5. Diferencias clave entre los tres tipos de código
| Tipo de código | Lo entiende el programador | Lo entiende la CPU | Se puede ejecutar directamente |
| -------------- | -------------------------- | ------------------ | ------------------------------ |
| Código fuente | Sí | No | No |
| Código objeto | No | Sí (parcialmente) | No |
| Ejecutable | No | Sí | Sí |
| Bytecode | No | No (requiere VM) | Sí, pero a través de la VM |
