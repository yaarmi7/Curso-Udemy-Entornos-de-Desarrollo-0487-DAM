# 6. Proceso de obtención de código ejecutable
Este apartado explica **cómo pasa un programa desde el código fuente que escribe el desarrollador hasta convertirse
en un ejecutable que la CPU puede ejecutar**.

Es uno de los procesos más importantes del desarrollo de software, porque determina:
* cómo se transforma el código,
* qué herramientas intervienen,
* qué archivos se generan,
* cómo se ejecuta finalmente el programa.

## 6.1. El papel del compilador
El **compilador** es una herramienta que traduce el código fuente a un formato que la máquina pueda entender.

### El proceso de compilación incluye:

#### Análisis léxico  
1. Divide el código en tokens (palabras clave, identificadores, símbolos).

#### Análisis sintáctico  
2. Comprueba que la estructura del código es válida según la gramática del lenguaje.

#### Análisis semántico  
3. Verifica tipos, variables, operaciones y coherencia lógica.

#### Generación de código objeto  
4. Produce instrucciones en lenguaje máquina, pero incompletas.

#### Optimización  
5. Mejora el rendimiento del código generado.

El resultado de esta fase es el **código objeto**.

## 6.2. El enlazador (linker)
El enlazador une:
* los distintos archivos objeto,
* las librerías necesarias,
* los símbolos externos,
* las dependencias del programa.

Su objetivo es generar **un ejecutable completo**.

Sin el enlazador, el programa no podría ejecutarse porque cada archivo objeto está incompleto por sí solo.

## 6.3. Intérpretes y ejecución directa
En lenguajes interpretados (Python, JavaScript):
* no se genera código objeto,
* no se genera ejecutable nativo,
* el intérprete lee y ejecuta el código línea a línea.

Esto hace que:
* la ejecución sea más flexible,
* pero generalmente más lenta.

## 6.4. Bytecode y máquinas virtuales
Lenguajes como Java o C# generan **bytecode**, un código intermedio que no es ejecutable por la CPU directamente.

Ejemplos:
* Java → .class
* C# → IL (Intermediate Language)

Este bytecode se ejecuta en una **máquina virtual**:
* JVM (Java Virtual Machine)
* CLR (.NET Common Language Runtime)

La máquina virtual:
* interpreta el bytecode,
* lo optimiza en tiempo real (JIT),
* lo ejecuta en cualquier sistema operativo.

Esto permite **portabilidad total**.

## 6.5. Sistemas de construcción (build systems)
Los sistemas de construcción automatizan el proceso de:
* compilar,
* enlazar,
* ejecutar pruebas,
* empaquetar,
* generar ejecutables.

Ejemplos:
* **Java**: Maven, Gradle
* **C/C++**: Make, CMake
* **JavaScript**: Webpack, Vite
* **C#**: MSBuild
Son esenciales en proyectos medianos y grandes.

## 6.6. Resultado final: el ejecutable
El ejecutable es el archivo final que el sistema operativo puede ejecutar directamente.

Ejemplos:
* Windows → .exe
* Linux → binarios ELF
* macOS → .app

Este archivo contiene:
* todas las instrucciones necesarias,
* todas las librerías enlazadas,
* metadatos del programa,
* información para el sistema operativo.

## 6.7. Resumen del proceso completo
1. **Código fuente** → escrito por el programador.
2. **Compilador** → genera código objeto.
3. **Enlazador** → une todo y genera el ejecutable.
4. **Sistema operativo** → ejecuta el programa.
5. **CPU** → procesa las instrucciones.

En lenguajes híbridos:
1. Código fuente → bytecode
2. Bytecode → máquina virtual
3. Máquina virtual → ejecución optimizada
